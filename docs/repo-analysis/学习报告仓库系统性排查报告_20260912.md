### 4.2 各仓库核心借鉴逻辑详解

#### InvokeAI — 「Z-Image 主线的现成参照」

InvokeAI 是 5 个仓库中**唯一已原生支持 Z-Image Turbo 和 Z-Image Base** 的项目，与 Image_MultiModel 的 Z-Image 主线完全一致。其核心价值不在于整库引入（体量 3,900+ 文件，React 前端与本仓异构），而在于：

- **diffusers 推理封装**：Z-Image 模型的加载方式、管线配置、参数映射可直接参照移植，避免从零摸索 diffusers 对 Z-Image 的支持细节。
- **Flux.2 Klein 对应**：用户本地已运行 Flux2 Klein(9B fp8)，InvokeAI 的 fp8 量化加载逻辑可减少试错。
- **合规安全**：Apache-2.0 与本仓同许可证，无 GPL 传染风险（区别于 ComfyUI 内核），代码可自由借鉴。

#### fluxgym — 「LoRA 训练 UI 的分层模板」

fluxgym 的核心价值是验证了「**轻前端 + 强后端**」的 LoRA 训练 UI 范式可行：前端用极简 Gradio（Advanced 标签默认隐藏），后端直接调用 Kohya sd-scripts 并暴露 100% 功能。这对本仓的启示：

- 若本仓做 LoRA 训练 UI，**无需自研训练后端**——直接复用/封装 sd-scripts 即可，前端只做参数编排与结果展示。
- 低显存预设（12/16/20GB 分档）与本仓低显存诉求一致，可直接参考配置策略。
- `models.yaml` 基模注册范式可移植到本仓模型管理，实现「选模型即下载」的即开即用体验。

#### sd-scripts — 「LoRA 训练的事实标准后端」

sd-scripts 是 LoRA 训练的**行业事实标准**，支持 SD/SDXL/SD3.5/FLUX.1/LUMINA/HunyuanImage-2.1/Anima 等广泛基座。其价值：

- **训练管线可直接参照**：`train_network.py` 的参数体系、元数据格式、采样策略是 LoRA 训练的成熟方案，本仓训练模块可直接移植或封装。
- **LUMINA 支持**：与用户本地 Lumina2 模型对应，若本仓做 Lumina LoRA 训练，sd-scripts 是现成训练器。
- **torch.compile 加速**（Anima LoRA / LLLite，提速约 20%）和低显存训练（LLLite）可作为本仓训练性能优化的参考。
- **关键缺口（已确认不支持）**：Z-Image 确认不在官方支持矩阵（复查报告全仓搜索 0 匹配，非「待验证」），若本仓主线为 Z-Image LoRA 训练，sd-scripts 不能直接用，需评估 AI-Toolkit 或自行扩展。

#### SDNext — 「量化与显存调度的深度参照」

SDNext 的核心差异化价值在**显存优化**：

- **SDNQ 量化引擎**：预量化或实时量化，最高 4× VRAM 缩减且质量/性能影响极小——这是本仓 fp8/gguf 量化路线的直接技术参照，其量化策略、质量权衡算法值得深入研究。（⚠️ 修正：SDNQ 量化非 SDNext 独有，InvokeAI 同样提供 `sdnq-quantization` 文档，若借鉴优先参考 InvokeAI——见顶部修正说明 T-02）
- **Balanced Offload**：CPU/GPU 显存动态平衡，让小硬件跑大模型——与本仓低显存运行诉求直接对应，其调度逻辑可借鉴。
- **Caption & Tagger**：内置 25+ LLM/VLM 标注工具，若本仓做训练数据准备流程，这是现成的标注能力参考。
- 注意：SDNext 是「all-in-one」大而全项目，应借鉴单点能力而非整库引入。

#### SwarmUI — 「架构思路的跨语言参考」

SwarmUI 的技术栈（C# / .NET 8）与本仓（Python）异构，**不宜整库引入或代码级复用**，但其架构思路有参考价值：

- **模块化后端设计**：后端与前端解耦，易扩展新模型——本仓多引擎热插拔架构可对照其模块化设计。
- **双界面 UX 分层**：Generate 标签（新手友好，自动工作流生成）+ Comfy Workflow 标签（专家模式，原生节点图无限制编辑）——这种「新手/专家」分层是本仓前端 UX 优化的方向。
- **视频模型集成**：MiniMax H3 / Wan / LTX-2 的集成范式对家族 MiniMax-H3-lite 参照价值更高。
